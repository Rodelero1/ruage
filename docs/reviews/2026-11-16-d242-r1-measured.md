# D242 - R1 measured: both halves of the game's answer cost more than they buy

**Scope.** `crates/sim/tests/replan.rs` (new, one fixture `#[ignore]`d). **No production code changed**: both halves of R1 were
built, measured and reverted in this session; their numbers are below.

## Performance

**Acceptance match, seed 7, 48,000 ticks, release, rebuilt for each row** (the queue's gate is entities **>= 155** and `repaths`
near **380**):

| build | entities | `repaths` (body / ground) | hash |
|---|---|---|---|
| HEAD (D237/D238) | **155** | **497** (139 / 358) | `8cf433ad4e0205f4` |
| half 1: `TakeAtRest` arm deleted | (not accepted) | - | - |
| half 2: re-plan keeps no avoid-tiles | **143** | **649** (252 / 397) | `b5de0f59aab9bf7f` |

Half 2 is a **-7.7%** loss of entities (155 to 143) and a **+30.6%** rise in re-paths (497 to 649) - the walker re-meets the same
men on every re-plan because the only memory it had of them was the ground set that was removed. **Wall time was not taken**: the
build was rejected on the gate before a timing run could matter, and timing a rejected build would put a number in a table no
reader can use. For scale, the baseline this gate measures against is **38.36 s** and **38.45 s** per 48,000-tick run on this
box (D237's two interleaved pairs).

## Stability

**Attack 1 - half 1 could not be measured against the gate, because it deadlocks.** With the arm deleted, the encounter fixture
behaves (`a_stopped_friend_is_not_walked_through`: 8,000 raw in an 8,000 reach, against 7,200 with the arm), and two existing
fixtures in `group_overlap.rs` fail: *"both have to arrive: a at (5,1), b at (5,2) after 2002 ticks"* and *"the two never came
within the reach"*. The game gets out of that stand with its **past** rule - the paused man stops moving, the other's re-plan is
stamped later, the stopped man becomes past - and that chain does not complete here. So half 1 is not "a deletion plus a fixture
fix"; it is a deletion **plus** the past-rule chain, which is now R1a.

**Attack 2 - the fixture that documents half 1 was proved red before it was ignored.** It was run against the unmodified engine
and failed with the defect in the message: *"the walker ended a tick 7200 raw from a friend standing still, inside the 8000 their
footprints need (tick 117)"*. With the arm removed it passes. It is ignored because the arm cannot go, not because the failure is
in doubt.

**Attack 3 - the fixture's own premise was wrong twice, and both times it was made to say nothing.** First draft: a friend who
had never moved. `is_past` answers *past* for him (`created >= 0`), and the game answers past for exactly the same reason - a
never-moved object's `lastMoveTime` is its birth - so the fixture was measuring the game's behaviour as a defect. Second draft:
the friend walks a tile **after** the route is stamped, which is the genuinely not-past case. Both were caught by running the
fixture against HEAD before trusting it.

**Attack 4 - the restated collision fixture went with the revert.** `collision::a_walker_never_ends_a_tick_inside_a_friend` was
restated to the stronger rule (no tick inside the reach) while half 1 was in, and restored with it: with the arm present the
walked-through step is the rule the fixture measures, and rewriting an assertion to match a change that is being reverted is how
a suite stops describing the engine.

**Not attacked, and why.** R2-R9 are untouched: each is its own slice, and mixing two adoptions in one measurement is how the
gate stops being able to attribute a loss to a change.

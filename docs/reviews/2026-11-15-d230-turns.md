# Review: the players take turns

*Change: `crates/sim/src/world/step.rs` (`step` gains the turn loop, `apply_turn`, `TickWork::bucket`,
`TurnWork::keep_the_standing` and `is_empty`, `World::turn_slot`, `TURNS`) and `crates/sim/tests/turn_order.rs` (new, two
fixtures). What it does: the tick's work is split into one turn per player - Gaia first, then 1-8 - and each player's share
is applied as a unit, so a man killed by an earlier player's blow does nothing for the rest of the tick.*

## Performance

**+4.8% for the mechanism, measured on a bit-identical match.** Built with every object forced into turn 0, the split
collapses to a single pass and the acceptance match is **identical to `main`** (`beb6c66f58e4045c`, 154 entities, 277
repaths), so the A/B compares the same work: **20.71 s against 19.76 s** over 24,000 ticks.

**An empty-turn skip halved that and was withdrawn**, because it broke two animal fixtures: `shepherd` resumes a gather on a
corpse from `self.slaughter` - world state, not one of the sixteen lists - so an empty turn still had work to do. The
saving was 2.5 percentage points of a tick; the cost was a second place for the rule to live. Its failing run is in the
record below.

**The real match costs +13.3% (22.64 s against 19.98 s, three interleaved pairs, spreads 0.2% and 2.2%), and most of that
is not the loop** - it is a *different* match: `hash=cb1f6a83a119a2a3`, 152 entities, `repaths=256` against
`beb6c66f58e4045c`, 154, 277. Separating the two needs a phase probe inside a live match; that is owed and named in D230
rather than guessed.

Supporting measurement: the ignored idle-world probe (`perf::idle_world_scales_with_entities`) at a fixed entity count,
before the empty-turn skip, read **650 -> 672 us/tick at 2,128 entities (+3.4%)** and +1.3% at 1,128 - the same order as
the same-match A/B, from a world with no work items in it at all.

## Stability

*Gate: 193 test binaries, **879 passed, 0 failed, 20 ignored** (877 before this change, +2 fixtures), `fmt --check` 0,
`clippy --workspace --all-targets -D warnings` 0.*

- **The whole suite passes unchanged.** No fixture outside `turn_order.rs` needed restating, which is itself the evidence
  that the split is not a re-ordering of *within*-player work: the same-player order is untouched, only the *between*-player
  order is new. (That is also the reason the two new fixtures are a swapped pair: they are the only place the change is
  visible.)
- **Three mutations, each reddening only what it should.** Deleted re-check: `the_higher_players_builder_lays_no_stone_when_he_dies`
  fails (the corpse lays stone). Reversed turn order: **both** fixtures fail, in opposite directions. Each mutation was run
  and its output recorded before the change was committed.
- **The liveness gate is stated twice on purpose, and the review says why.** `bucket` judges health at the tick's opening
  and `keep_the_standing` judges it again when the turn comes; a single check at either point alone leaves the rule
  reachable in one direction only (measured: the deleted re-check reddens the fixture that needs it).
- **The split cannot reorder a player's own work.** `bucket` appends in list order, and each list is filled by `decide` in
  entity-id order, so a turn's items keep the order they had. The D229 sort of `strikes` is now redundant within a turn and
  is kept anyway - it sorts by `(player, id)`, which inside one player is the id, so it is a no-op and cannot fight the
  turns.
- **A resource node is not "dead".** `turn_slot` treats `hp == 0` as dead **except** for `EntityKind::Resource`, because a
  node carries `hp = 0` by construction and still has to lay its gather ring (`respreads`). Without that exception the
  ring-laying pass would silently stop running - a silent stall of exactly the kind this tree's invariants are about.
- **Empty turns are skipped, and that is safe by construction**, not by measurement: a turn is a set of lists, and a set of
  empty lists is thirteen calls that do nothing.

Known and accepted:

- **Inside a player's turn the objects are still simultaneous.** The work is applied phase by phase, not object by object,
  and `decide` still reads the tick's opening state, so an object cannot see what an earlier object of the same player
  did. This is the inner loop, and it is where T12 finishes; the outer loop is what this slice bought.
- **Movement, production, arrows, world timers and the death sweep stay global** after all the turns. A unit killed in
  player 1's turn can still take its movement step this tick (D229's production gate covers buildings only). Named in D230.
- **The match diverges**, and that is a behaviour change on the record: `hash` and entity counts move, `repaths_body` falls
  68 -> 49. A replay recorded before this commit will not reproduce after it.

## My own errors

1. **The first version of the gate only checked health at the split**, so the fixture it was written for stayed red: the
   split runs before any turn, and by the time player 2's turn came the builder was dead in the world but alive in the
   bucket. The re-check is the fix, and its deletion is now one of the mutations.
2. **The first fixture guessed the foundation's id** (`EntityId(910)`) and reported "the builder never started working" -
   the engine allocates that id, so the test was watching a slot that did not exist. It now finds the player's foundation.
3. **A timing A/B taken on the diverged match was quoted to myself as the loop's cost** (median +16.9% over three pairs,
   one of which ran at 30.71 s while the box's load average was 2-3). The forced-one-turn build is what made the number
   honest: same match, same work, +4.8%; re-running the diverged A/B on a quiet box gave 22.64 / 22.65 / 22.61 s against
   20.09 / 19.98 / 19.66 s.
4. **The empty-turn skip passed my reasoning and failed the suite.** "A set of empty lists is thirteen calls that do
   nothing" is false for `shepherd`, whose tail reads `self.slaughter`; `animals::a_live_animal_is_a_gather_source` and
   `the_shepherd_kills_the_sheep_and_the_gathering_resumes_on_the_body` both failed with the skip in and both pass without
   it. The optimisation is out of the commit and this note is why.

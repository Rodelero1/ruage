## Performance

**The parser costs the same, measured like for like on the same corpus text**: `parse_decisions` at **515.8 ms** against
**536.3 ms** for `HEAD`'s parser (`git show HEAD:tools/decisions.py`, both run five times on the *current* 554 KB file, minimum
taken) - 245 decisions either way, and the difference is inside the run-to-run spread, so it is called **unchanged**, not
"4% faster". The change adds one loop over a list that is empty by construction, which is why nothing was expected from it.

## Stability

What was attacked:

1. **The test came first and was watched red**: `SupersedeDirection` failed on `['D1'] != []` before `decisions.py` was touched
   (`Ran 1 test ... FAILED`), and the first fix was **wrong** - parsing the passive form with a direction flag fixed the inversion
   and then marked **D208** superseded by D192 for writing a sentence about a *document*. That moved the red set instead of
   shrinking it, which is the tell this repo already has for a wrong model, so the passive form was dropped rather than tuned.
2. **The corpus was asked what it actually contains, not what the prose says.** Six supersede links survive the change
   (D9->D10, D46->D59, D59a->D59b, D70->D116, D117->D239, D152->D183) and both false ones are gone; the four corrections
   (D13, D31, D44, D54) are untouched, and duplicates in the lists are now refused so a sentence naming the same pair twice cannot
   render "superseded by D10, D10".
3. **The duplicate id was found by reading every heading, not by trusting the count.** Two `### D200 -` sections parse as one
   decision plus one amendment (`versions: 2`), so `--check` was green while the index showed the **parked** title for the shipped
   rule. Splitting the parked one to **D200a** keeps both bodies, keeps `check_shrink` satisfied (D200 is still defined), and makes
   the id mean what 40-odd citations mean by it.
4. **Nothing was deleted, and the check that would catch it was not relaxed.** `check_shrink` is untouched; the markers are
   additions. A future session that decides to "tidy" by removing bodies will be refused by the same script it is meant to be
   tidying for.
5. **The new register rows were verified before being written.** Rows 31 and 35 were read in the code (`walk_goal`,
   `plan_path`'s pencil-first order); rows 34 and 35 were checked against the **exe's own strings** (`due to pause reason`,
   `Looking for a STRAIGHT LINE path` - one hit each, `grep -ac`, 2026-11-16); rows 33 and 36 carry a **sibling session's read,
   labelled in the row as not re-read here** rather than promoted to fact. Two of that thread's candidates are recorded as
   deliberately *not* rows: the per-path continue counter (instrumentation no rule reads) and DE's Collide & Correct (a later
   build's mechanism).

**Not done, and named rather than hidden:** the re-seed (row 33) and the path vocabulary (row 36) are queued as **R8** and not
built; row 32's thing-order half stays `unknown-static`; and the class of decision that is dead with **no superseder** (a slice
reverted by measurement - D141, D236) still has no marker, because recognising it needs a per-decision symbol probe that is not
written.

# Review: the farm base was the Horse Collar figure, and the Chinese bonus never landed

*Change: a plot's food base is the civ's own `resources[36]` - **175** in every playable row of the dat, 0 for Gaia - which
content already names via `[farm] food_resource`, instead of a content constant that had been authored as **250**. The
content value survives only as the fallback for a pack whose players have no civ. `farm_food_base` reads the row,
`farm_food_bonus` now sums the researched techs **and** the civ's team bonus, and the upgrade's proportional share uses the
same base. D215.*

## Performance

**No per-tick path, and the number that moved is the match, not the frame.** The change adds one lookup - the player's
`resources[36]` - at the moment a plot is marked out, and one more sum over the civ's bonus effects when a tech lands.
Neither is in the tick.

What the acceptance match does, on the same command as every previous baseline (`seed 7`, 48,000 ticks):

| | before (`7a26ac5`) | after |
|---|---|---|
| hash | `42212c8e852b62be` | `4640552242d6b45b` |
| entities at the end | 144 | 148 |
| `repaths` | 380 | 552 (+45%) |
| outcome | `players=1` (won) | `players=1` (won) |

**That is fidelity being paid for, and it is the honest cost of this slice**: a plot holds 75 less food, so a villager reseeds
about 43% more often and walks to do it - which is exactly what `repaths` measures, and why the reseed queue (T6, item 6 on
`docs/next-step.md`) is now worth more than it was. Wall clock on the two runs was **83.5 s and 66.5 s**, against 42.0 s for
the same script before; **no claim is made from those**: the box was at load 4.77 on 2 CPUs with another session's work, and
the two runs of the *same* binary differ by 25%. A wall-clock comparison of two different matches under that load would be
noise dressed as a result.
## Stability

- **The upgrade arithmetic is the trap, and it had to move with the base.** Horse Collar's +75 goes onto a plot *in
  proportion to what is left* (the owner's rule, D77), so the share divides by the plot's **original** total. That total is
  now the civ's base, and `was_total` takes it from the same function the plot was created from - a constant there would
  have given a half-eaten Chinese farm its share of the wrong budget (220 against 175). The half-eaten fixture was restated
  from 250/125 to 175/87, and its measured share is **37** (75 x 87 / 175 = 37.28, floored) instead of 37 of 125.
- **A test that hard-coded the old base was hiding a second defect.** The new Chinese fixture failed on **250** before any
  change was made: `farm_food_bonus` walked the researched techs and never the civ's `bonus_effects`, so the Chinese team
  bonus - a resource-36 `add` of 45 - applied to nothing. Two defects in one line of code, and only the per-civ test could
  see the second: a test that asserts one number for one civ cannot tell "wrong base" from "missing bonus".
- **The fallback is exercised, not assumed.** `a_farm_holds_only_what_content_gives_it` builds a world with **no** civ row and
  overrides `food_per_farm` to 20, so the content path is covered; if the civ lookup ever starts returning a value for a
  player with no civ, that fixture fails immediately rather than silently preferring the row.
- **Data read, not assumed.** A probe over all 32 civs: `resources[36] == 175.0` for every playable one, 0 for Gaia, with
  `resources[84] == 3` and `[88] == 700` agreeing with the U8 answer already recorded - so the row is the same table the
  mechanics notes describe, not a coincidence at one index.

Known and accepted:

- **`boom_probe` and the acceptance match move**, because every plot now holds 75 less food and each villager must reseed
  sooner. That is the point of the change; the measured acceptance result is in the perf section and recorded in the skill's
  farms note so the next session starts from the right baseline.
- **Gaia's row is 0 and that is correct**: no Gaia plot should hold food, and the fallback covers a Gaia player in a
  hand-written pack (nobody plays Gaia).

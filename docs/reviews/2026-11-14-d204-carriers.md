# The carrier half of D204, parked: the named observable does not witness the rule

**Branch `d204-carriers`, cut from `main` at `46cec66`. No production code changed.** One fixture,
`crates/sim/tests/carrier_no_pushing.rs` (seven villagers filling and carrying home from one bush to one town centre),
committed `#[ignore]`d with the measurement in its header, because the assertion it was specified with cannot go green.

## The rule, and the observable it was specified with

`push_the_standing` (`crates/sim/src/world/step.rs:907`) skips a body with a **gather** order (`step.rs:989`). The slice
was to extend that to `Task::Gather | Task::Return`, and to watch it fail first with `World::made_room() == 0` in a crowd
where every body has a gather or return order.

**`made_room()` is not the displacement counter.** It counts the *walker's own* make-room step - `pass.made_room` is
pushed at `crates/sim/src/world/movement.rs:400` (C1b's "make room, once per route") and turned into
`made_room_count` at `step.rs:1317`. `push_the_standing` moves the **standing** body by writing `entity.position`
(`step.rs:1040`) and increments no counter at all. The two mechanisms are different passes of the same tick, and no gate
inside the second can move the first.

## Performance

- **The acceptance run is byte-identical with the gate and without it**: `entities=160 players=2
  hash=c3b10f4b09e17a43 repaths=324 made_room=147 repaths_body=83 repaths_ground=241`, wall **30.2 s**, food
  `45 / 49 / 268 / 120 / 660 / 450`, wood `80 / 96 / 135 / 75 / 395 / 185`, units `20 / 31 / 35 / 44 / 46 / 48` - the same
  hash, the same counters, both ways. The gate fires on **zero** candidates, so its measured cost is 0 s and its measured
  benefit is 0 displacements.
- **The specified fixture, `crates/sim/tests/carrier_no_pushing.rs`, `--ignored`, 4,000 ticks**: `made_room() == 7` on
  `main` and **also 7** with the gate extended (`MEASURED the crowd displaced 7 time(s): 3 gathering, 4 carrying home`).
  Red before, red after: not a test of the rule, a test of the walkers' own give-way.
- **`push_the_standing`'s census over the acceptance run, measured by printing the task of every body it moved**:
  `main` (post-D204) **161** moves - **147 `Build`, 12 `Attack`, 2 `Idle`, 0 `Return`, 0 `Gather`**; `7d00be8`
  (pre-D204, same seed and ticks) **310** - **232 `Build`, 76 `Return`, 2 `Idle`**, reproducing the D204 addendum's
  number exactly. The 76 loaded carriers were a property of the match **before** D204; the match D204 left behind
  displaces none of them.

## Stability - what was attacked

- **Where a `Return` body stands in the candidate loop.** Instrumenting the selection (`step.rs:967`-`1005`) over the
  acceptance run: **22,253** considerations of a `Return` body as the body in the way, and **every one skipped** before
  the nudge is reached - 13,509 by `busy && !jammed` (walking home), 7,048 by `posted` (jammed, still holding a reserved
  gather place), 1,696 by `posted` as well. Zero eligible. The gate would be dead code in this tree, and dead code that
  a future change to `posted` or to `stalled` could silently reactivate.
- **Three fixture shapes, none producing a single displacement.** The seven-villager crowd above (4,000 ticks); twelve
  villagers on one bush with a one-tile gap to pass (8,000 ticks, `made_room=8`); eight villagers shuttling through a
  **one-tile-wide corridor** with walls both sides between bush and town centre (6,000 ticks, `made_room=8`). The
  corridor's census: **2,598** `Return` candidates, **0** eligible, **0** moves - the carriers there are `posted`
  (they hold their ring place while walking home), so the `posted` skip takes them first.
- **Determinism**: the gate changes nothing, so the hash is unchanged (`c3b10f4b09e17a43` measured twice, once with the
  gate and once without). `no_float` untouched: the fixture's arithmetic is in the test, and the engine was not edited.
- **The probe was checked against the tree it describes**: the same print on `7d00be8` reproduces 310 / 232 / 76 / 2, so
  the 161 / 0 reading on `main` is not an instrument fault.

## What is left, stated as the unknown it is

The one case the gate would cover is a `Return` carrier who is **jammed (`stalled >= 40`) and holds no gather place**.
No fixture I built reached one, and the acceptance match no longer contains one. If the owner still wants the rule, the
work starts by finding that body - a jam at a drop site whose carriers have lost their ring places - and then watches a
**position** assertion fail (the shape `a_crowd_at_a_tree_is_never_pushed` already uses), not `made_room`.

# D243 - the owner's four body invariants as fixtures: two hold, two are red

**Scope.** `crates/sim/tests/invariants.rs` (new, four fixtures: two green, two `#[ignore]`d with their violation in the ignore
message). **No production code changed.**

## Performance

**The four fixtures cost 3.42 s** for 2,000 ticks of a four-villager economy, checked on every tick (8,000 body checks plus the
pair matrix) - about 1.7 ms per tick of test time, all of it outside the engine. Nothing lands on the tick path, so the
acceptance match is unchanged at `8cf433ad4e0205f4` / 155 entities / 497 repaths, which is the D237 baseline and what the queue's
gate measures against (**38.36 s** and **38.45 s** per 48,000-tick run on this box).

## Stability

**Attack 1 - the fixtures could pass by measuring nothing.** The scene is built from content and refuses to be empty: it finds
four resource nodes and a town centre, refuses a spawn tile that is not `is_free_ground` (the first draft got `NoPath { from:
(23, 15), to: (20, 15) }` and every test failed in setup), and each fixture fails loudly if its own check never fires. Rules 1-4
were each run against the engine and produced either a pass or a **named tick** - never a silent green.

**Attack 2 - a task test is not "he is working".** The first version of rule 2 judged any villager whose task was `Gather`, and
flagged a man **0.371 tiles** out who was simply walking to his tree - the approach carries the same task. The rule now needs
`progress > 0`, which is the engine's own "he is taking from it now", and with that gate the invariant holds. The same mistake in
rule 4 would have flagged every approach step; its `gap <= radius` gate is the conservative half of the same idea, and it is why
that fixture's violation is a **0.011-tile** step rather than a walk.

**Attack 3 - the two reds are not the fixture's fault.** Both were re-run with `--ignored` and both report the engine's own
numbers: *"tick 792 … delivered 10.00 of a load with his body 0.281 tiles from the drop building"* and *"tick 11 … moved 0.011
tiles while gathering from node 11, which still holds 100.0"*. A fixture that could not distinguish a defect from a slow test
would report a walk; these report a *drop* and a *settle step*.

**Attack 4 - "one diameter" could be read two ways.** It is the body's own two radii (0.4 tiles, radius 0.2), which is also how
`reach_between` and the standoff are defined everywhere else in the engine - so the fixture and the engine agree on the yardstick,
and the crowd case (`overlap::eight_villagers_ordered_to_one_tile_never_walk_through_each_other`) already pins rule 1 against a
harsher scenario than four men on four nodes.

**Not attacked, and why.** Neither red was fixed here: rule 3 changes when every delivery in a match happens, and rule 4 removes a
step from the settle path that places men round a node. Both move the acceptance match, so each needs its own slice and its own
measurement rather than a quiet edit under a test.

# Review: the shoulders the doc promised - the search now bends round a body in an open window

*Change: `short_range_clear` gains the eight shoulder nodes per body it always claimed to have, a straight-line shortcut
that asks the discs before it answers, and one rule - `step_out_ok` - for every step that leaves a body the walker is
already inside. D211 (bodies as discs with a circumscribing octagon), D212 (the `2 x clearance` re-seed that only moves
away). `group_overlap::a_mate_who_is_stopped_becomes_solid` was the last red guard on the branch; it is green, with its
expectation restated to the rule the engine actually has.*

## Performance

**Measured, interleaved A/B, same config and seed, on this box (2 vCPU):** the acceptance match
(`--script config/acceptance.toml --seed 7 --ticks 48000`, release, each binary built in its own checkout with its own
`CARGO_TARGET_DIR`), two runs each:

| run | wall | outcome |
|---|---|---|
| `main` (`e0312f9`) | **30,970 ms** | `entities=160 players=2 hash=c3b10f4b09e17a43 repaths=324 made_room=147 repaths_body=83` |
| branch | **42,378 ms** | `entities=133 players=1 hash=bffe63e30295ddb8 repaths=765 made_room=0 repaths_body=446` |
| `main` again | **30,757 ms** | identical to the first |
| branch again | **43,049 ms** | identical to the first |

**The two runs are not the same match, so the wall-clock difference is not a per-tick cost.** The branch's match is **won**:
the script's last refusals read *"no enemy matches `enemy_town_center`"* and *"the match is over"* at about **2,387 s** of
game time, i.e. the enemy town centre is razed inside the 40:00 the acceptance row asks for - which `main` misses (D200's
review records its town centre at 1,451 of 2,400 hp and the match unfinished at 48,000 ticks). More of the world is moving
and fighting, and `repaths_body` is **83 -> 446**, so the extra 11-12 s is *more work*, not slower work.

**What that means for a per-tick claim: none is made here.** The honest statement is that the wall-clock is **+37%** on the
same command while the command is no longer doing the same thing, and a like-for-like figure needs the `perf` probe at a
fixed entity count (it is `#[ignore]`d, `crates/sim/tests/perf.rs`). What the change cannot move is the per-tick pass when
nothing plans: `short_range_clear` runs per *plan*.

**Where the extra plans come from, and the number still owed.** Two things, both reported rather than buried: D211's
straight-line shortcut no longer answers before the discs are read (so a plan near a body now builds a graph instead of
returning), and the tie-break no longer pauses the loser *itself* (see Stability), so the loser falls through to the
collision block and asks for a route where it used to stand still. `repaths_body 83 -> 446` is that bill. It is bounded by
`Route::avoiding` ("known") and `MAX_REPATHS_PER_TICK`, but D135's "one search a tick" is exactly the shape to watch, and
`perf.rs` at a fixed entity count is the next measurement - first item of the next slice, with `last_moved`.

## Stability

### The freeze the fixtures found: a loser that pauses itself stands for ever

Found while triaging the branch's inherited failures, and it is the worst class of bug this project has: **a unit standing
still for the rest of the match**.

`vision::an_enemy_is_only_visible_while_somebody_watches` failed with the scout at `(614150, 614150)` and `step = Paused` from
tick 50 to tick 550, with a live route. The cause is in the tie-break: our version pushed the pause for the *mover itself*
and returned, so the mover never reached the rest of the collision block - and the rest of the block is where its own answer
lives (a re-plan round the body, or a step into a body at rest). Against a man with no order who never moves, the collision
is still there every tick, so the loser is stood up again, for ever. The original only ever calls `setPause` on **the other**
unit (`008a80ff cmp eax,esi / jle`), and the mover that loses the comparison simply goes on to the next rule.

Fixed test-first: `right_of_way::a_loser_does_not_stand_for_ever_against_a_man_who_never_moves`, watched failing with the
walker parked on the stander's own tile for 2,000 ticks and green after removing the self-pause. It closed `vision`'s fixture
and one `rally` fixture on its own, and it is why the acceptance match now ends with the enemy eliminated (see Performance).

One fixture restated with it: `right_of_way::the_higher_id_pauses...` asserted the paused unit's waypoint list is
*unchanged*. It may now be **replaced** (the loser re-plans round the man while it stands) and must not be **spent**; the test
asserts the destination is unchanged and the man arrives.

### The slice itself

**Four defects, three of them pre-existing and all found by measurement rather than by reading:**

1. **The straight-line shortcut ignored the bodies.** `blocked.is_empty()` returns the route *before* `bodies` is read, so
   a window with no blocked tile answered "straight line" whatever stood in it. Measured on
   `group_overlap::a_mate_who_is_stopped_becomes_solid`: closest **5012 raw** against an 8000 reach, with the re-plan that
   *was* asked for producing a route whose second leg passed **0.25 tiles** from the stopped man's centre. Pinned by
   `clearance::a_body_alone_in_an_open_field_is_rounded_like_a_wall` (red at **0 raw**, green now).
2. **`clears_disc`'s endpoint case was an OR.** With the perpendicular foot outside the segment the nearest point is an
   end, so the segment is clear only when both ends are; the code said "either end", which passes any line that ends far
   away - including a line from inside a man to a free point beyond him. Found because fixing the shortcut alone left the
   route running *through* the body at 86 raw. Pinned by the same two fixtures, which both measure the route's own distance
   from the centre.
3. **The eight shoulder nodes did not exist.** `short.rs:72` and `docs/reviews/2026-11-14-d211-clearance.md` both described
   them as built. `grep shoulder crates/sim/src/short.rs` found the comment and nothing else - and the two `clearance.rs`
   fixtures passed anyway, because the stander's *tile* was in the avoid set, so a whole-tile rectangle existed to bend
   round and no test ever asked for a sub-tile bend. That is the "a tested function nobody calls proves nothing" trap with a
   documentation-shaped lid: the tests were green and the mechanism was absent. The new fixtures call `short_range_clear`
   directly, with a hand-built `Walk` and no world under them, so nothing but the search can satisfy them.
4. **The re-seed was allowed to anchor on the far side** of the body (its own `clears_disc` call had defect 2), so "get
   unstuck" could mean "hop over him": measured **3702 raw** against 8000 in the earlier pass, worse than the 4207 it was
   fixing. The anchor now uses the same predicate as the graph's first edges - a step out must move **away**.

**Two tests restated, each with the reason and the measurement written into it, and each still able to fail:**

| test | was | now | why |
|---|---|---|---|
| `group_overlap::a_mate_who_is_stopped_becomes_solid` | "never inside the reach" | at most **one step** of overlap at the meeting, nothing inside the reach on any later tick, and he arrives | D210 withdrew the clamp against a body and rule 6 takes a full step into a body at rest, because a resting body cannot move aside. Measured 272 raw of overlap at the meeting - and the route the walker then takes keeps **8664 raw**, the octagon's tangent distance |
| `right_of_way::the_higher_id_pauses...` | both orders submitted in one tick | the second order lands a tick later | orders in one tick are a **group** (D207) and a mate is dropped before the tie-break, so the fixture could never see the rule: measured **1 tick** of stand as a group, and the drawn 0.25-1.50 s with the orders a tick apart |
| `right_of_way::two_units_jammed_on_the_same_tile...` | a pause, and "never inside the reach" | both finish the crossing, and the stand is bounded at 1.50 s | the pair start 0.45 tiles apart and each takes 0.04 tiles a tick, so they are inside the 0.40 reach by the second tick; from there D52 ("a body already overlapped is not made worse by moving") governs and the tie-break never runs. The "never inside" clause is the one D210 withdrew |

**The guard's own numbers, in order:** 4207 (the route ran straight through) -> 5012 (a re-seed that hopped over him) ->
**7728 at the meeting only, 8664 afterwards** (an octagon round him, and he arrives). Each step is in `docs/next-step.md`
and the gate's failing set was re-triaged on a tree with a **real** pack - the previous session's "green" was measured in a
worktree whose `config/gamedata/` did not exist, and every fixture there returns early without running an assertion.

Known and accepted: the octagon's vertices sit `1.083 x clearance` from the centre, i.e. **0.9 raw units** outside the
exact circle for two villagers - tangent edges cannot be exact in integers without either cutting the circle or adding
that hair of slack. `short_range` (the tile-corner search used by callers that pass no bodies) is untouched, so a plan that
takes that path still has no sub-tile detour. And the stander set that would feed this search every tick is **still
inert** - `last_moved` is stamped on zero deltas, so `stander_bodies` returns nothing; see D210's defect and
`docs/next-step.md`.

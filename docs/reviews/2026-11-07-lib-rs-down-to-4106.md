## Performance

- **No measurable change, and the design forbids one**: this is a move inside one crate, so `rustc` still sees one codegen
  unit per function; a `pub(crate)` call across modules inlines exactly as an intra-`impl` call did. Nothing was inlined
  differently, nothing was re-ordered — the acceptance hash and all 188 repaths / 187 made-room are identical.
- **Build time went up slightly**: a cold release build of the rearranged crate was 1m21s at D144's four slices. Two cold
  builds of the sixteen-file layout were 1m24s and 1m26s. That is inside noise and is not claimed as a regression; what *is*
  claimed is that no build-time work was added deliberately (no generic-heavy abstraction, no trait objects).
- **The one perf-shaped risk was `step`**: a 1,566-line function moved into its own file is still a 1,566-line function, so
  the optimizer's inlining decision is unchanged (it cannot inline across a call it never sees, and it never saw one).

## Stability — and two real defects this pass found

1. **Four methods silently lost `#[must_use]` — and their doc comments with it, which is worse.** The extraction walks back
   over `///` and `//` lines to take a method's doc comment with it, but **not over `#[…]` attributes**, so the
   `#[must_use]` line blocked the walk: the attribute stayed behind in `lib.rs` (compiler: *"unused attribute"*) **and the
   documentation stayed with it** — `in_strike_range`, `card`, `site_fits`, `site_has_lane` arrived in their new files with
   no docs. Clippy then caught the leftovers a second time (*"empty line after doc comment"*, twice), because the orphaned
   doc block had become a dangling comment above the next method.
   **Both were fixed by moving the stray doc block into the new file**, and the audit is now mechanical: all **42**
   must-use methods from `HEAD` are checked for their attribute and their docs against the new layout; none is missing, and
   46 attributes are present across `src/`. **This is a move-tool defect, not a code defect**: the same walk-back had
   already run in D136 and D144 without loss because those groups happened to contain no must-use methods. The skill's
   recipe carries the rule: *walk back over attributes, not just comments, and re-check the doc block by hand at every cut*.
2. **`pub pub(crate)` twice.** Making a helper visible with a text patch that appends `pub(crate) ` to a signature which was
   already `pub` produced `pub pub(crate) fn max_scale_for` — a compile error, caught immediately, but the real finding is
   that `max_scale_for` and `MAX_PLAYERS` are **public API** and a careless promotion would have *narrowed* it. Rule kept:
   only ever promote a signature that starts with exactly four spaces and `fn `.

**The proof of no behaviour change is the hash, per move, not reading the diff**: `f328ebc8d4d34b78`, 141 entities, 188
repaths, 187 made-room — checked after each of the twelve moves in this pass, identical every time.

**The suite is unchanged in size and green**: 728 passed / 0 failed / 19 ignored, no test moved and none added, clippy
`-D warnings` clean, `fmt --check` clean.

## What is still big, stated plainly

- **`world/step.rs` is 1,581 lines and one function.** The file split did not make the tick easier to read; it made `lib.rs`
  navigable and put the tick in one place. Cutting `step` into named phases — order intake, walking, gathering, building,
  training, research, combat, bookkeeping — is **stage 2**, is not mechanical, and is worth more than everything in this
  commit.
- `battle.rs` at 665 is the next honest candidate for a split (skirmish vs. projectiles vs. aiming), and `orders.rs` +
  `sites.rs` overlap on placement questions, but neither is urgent.
- **`git blame` churn**: this pass moved ~3,400 lines, so those lines' history now points at one commit. Every doc comment
  moved verbatim, so the sentences are still findable by `grep`.

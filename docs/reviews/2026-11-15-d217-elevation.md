# Review: elevation is held at one, with a site and two tests that bite

*Change: `combat.toml`'s elevation pair is loaded into `World::elevation_above` / `elevation_below` and applied by
`World::elevation_factor` at the single damage site - called with two heights that are always **0**, so the factor is exactly
one and a hit is unchanged. Two tests: a spear's **4** against a villager stays four (1.25 would make it five, and the content
still says 1.25), and a zero/negative/infinite multiplier is refused at load naming its key. D217.*

## Performance

**The term costs between 1.1 and 5.7 ns per blow**, measured as the difference between `damage * scale / scale` and the bare
sum over a million iterations of five damage values (`crates/sim/tests/perf.rs`, ignored probe
`the_elevation_multiply_per_hit`): **+5.742 ns**, **+1.107 ns**, **+1.323 ns** on three runs. The ~27 ns both sides pay is
the probe's own `black_box`, so the difference is the one 64-bit multiply-and-divide the term adds - and a spearman blows once
every two seconds, so a whole match's worth of blows is below a millisecond.

**No value can move, and that is asserted rather than argued.** The factor is `Fixed::from_raw(scale)`, so
`damage * scale / scale == damage` exactly for every damage the earlier arithmetic produces (i64, no remainder). The damage
fixture pins **4** where 1.25 would give 5, so the acceptance match's hash cannot change by this slice - the current figure on
the same command is `hash=beb6c66f58e4045c` at 24,000 ticks, `entities=154`, `repaths=277`.

## Stability

- **The term is applied, not commented.** `grep elevation crates/sim/src` used to find nothing but a doc sentence; it now finds
  one field pair, one function and one call site. That is the difference between "we do not do elevation" as a promise and as
  a structure, and it is what the tree's row asked for.
- **Both tests were proved by mutation, because neither could be red on the day it was written.** Forcing the above-ground
  branch makes the damage fixture fail `left: 5, right: 4`; removing the loader's guard makes the refusal fixture fail with a
  0.0 multiplier loaded. A guard that is never exercised is indistinguishable from a comment, and this project has paid for
  that twice already.
- **The multiply is exact and the test says so.** The factor is `Fixed::from_raw(scale)`, so `damage * scale / scale == damage`
  for every damage the earlier arithmetic can produce (i64, no remainder). If a future height ever makes the factor 1.25, the
  same test that pins 4 will fail on purpose - and that is the signal to restate it with a height, not to loosen it.
- **The refusal test names three shapes** - zero, a negative and an infinity - because each has a different failure mode:
  zero wipes a hit, a negative inverts damage, and an infinity would overflow the i64 multiply into an absurd `i32::MAX`
  clamp. The loader already refused all three; nothing had proved it.

Known and accepted:

- **5.7's multipliers are not verified** (U4's residual). 1.25/0.75 is the AoC-published pair; the provenance note says so, and
  a save with a unit fighting uphill would settle it. Not invented, not asserted.
- **`elevation_factor`'s heights are literals at the call site.** When the scenario importer brings an elevation layer, that
  line becomes two reads and this function is already the only place that has to understand them.
- **Terrain *types* are not elevation.** Grass, dirt and forest floor are ground; a forest floor is not lower than grass. The
  test deliberately does not pretend otherwise.

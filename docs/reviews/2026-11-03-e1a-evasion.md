# Review: E1a - the evasion machinery, on a tile predicate

*Change: D98a's first slice, as the owner ruled ("E1a now, then S1 ... as proposed"). `World.paths` holds a `Route`
(steps plus the bodies the route is planned around) instead of a bare waypoint list; the movement apply-loop tests the
tile a step lands in against the bodies standing there and classifies the hit - the order's target means arrival, a body
already in the route's avoid set is *past*, anything else is **non-past** and is collected for a repath; repaths are
planned after the loop with `find_path_avoiding`, keep the old avoid set and add the new body; a failed search records
the body as past anyway and puts the refusal in state. Four tests in `crates/sim/tests/evasion.rs`, plus `repaths()` as
instrumentation.*

## Performance

**The tick, measured on the acceptance match** (36,000 ticks, seed 7, release): **10.8 s wall, ~0.30 ms/tick** at 160
entities. The same run before this slice finished faster and no longer holds: see below - the cost is not the collision
test, it is that more villagers are working for longer in a run that does not end.

**Two performance defects found by running it, not by reading it:**

1. **Every projectile stopped dead over the first body it crossed.** The collision test ran for anything with a delta,
   and an arrow is an entity that moves through the same pass: ten arrows froze mid-air over the town centre and
   `a_town_center_shoots_a_spearman_five_tiles_away` went red. The test is now about `EntityKind::Unit` only.
2. **Repath thrash, which was a hang.** A crowded fight re-planned every tick, and a *failed* repath left the body out of
   the avoid set, so the same whole-map search ran again next tick: measured at **2,874 collisions in 100 s** of test wall
   clock with the fixture not reaching tick 5,000. Two fixes, both from the original's shape: a failed search still
   records the body as past, and a tick may spend at most `MAX_REPATHS_PER_TICK = 4` searches (a performance budget, the
   `max_entities` kind of constant, not a game value). After them the same fixture plays 40,000 ticks in **4.2 s** with
   **69 repaths in total**.
3. A body the unit is already adjacent to is not repathed at: re-planning cannot improve on standing beside the goal, and
   the arrival rules finish the order. That removal is what took the "body on the goal" case from one repath to zero.

A repath costs what the pather costs: **28 µs** plain and **125 µs** with one avoided tile, corner to corner on the
project map (measured in the previous commit).

## Stability

- **The world's outcome moved, and that has to be said in the same breath as the green suite.** The acceptance match at
  30:00 game time now ends with **both players alive** (`players=2`, hash `7c0b9132ed2074f8`) where it won for player 1
  before (`players=1`, `98c1c2a051d044f6`), and its economy is visibly weaker by 400 s (95 wood / 0 food against
  70 / 40). Villagers that no longer share a tile queue at a bush and at a drop site. The suite's acceptance test asserts
  the *opening* runs without refusals, so it stays green; the match it plays no longer finishes. That is the cost of the
  rule as ruled, not a defect to paper over, and it is the first thing the next slice should be measured against.
- **Two fixtures parked, with their diagnosis rather than a guess.** `a_damaged_building_ejects_its_garrison` (melee
  attackers cannot close on a building whose goal tile is blocked - 1,066 of 2,400 hp instead of 480, all twelve alive,
  standing 1-4 tiles off with `cooldown_ticks: 0`) needs the adjacency-ring arrival that E1b brings. `a_forager_whose
  bush_is_finished_goes_to_a_farm` picks node **103**, another food source, instead of the adjacent farm, with **no
  refusal recorded** - a choice, not a rejection - and the cause is not yet read.
- **The avoid set is state and is hashed** (only when non-empty, so a world that never collides hashes as before), and it
  lives *with* the route so a new order cannot inherit the old plan's blind spots.
- **Determinism**: the decision is per entity in id order, the repath budget is spent in the same order, and the avoid
  set is a `BTreeSet`. Two runs of the same commands still agree - the evasion tests and the scenario suite pass with the
  same hashes within a run.

Known and accepted: the collision test is **tile** granularity, so two bodies can stand 0.05 tiles apart across a tile
line and pass; the radius form is E1b. `unit_tiles` is rebuilt on every tick where something moves (O(bodies), one
`BTreeMap`), beside the existing occupancy grid.

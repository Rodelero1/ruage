# D235 - the world writes itself down, and a load is proved by ticking the same (P1a)

**Scope.** `crates/sim/src/world/snapshot.rs` (new: `Written`/`Read`, `World::state`, `World::from_state`), `serde` derives on
`World` and its 24 field types plus `Fixed` (`crates/fixed`) and `Footprint` (`crates/data/src/economy.rs`), `crates/data/src/
pack.rs` (`civs` becomes a field), `crates/sim/src/error.rs` (`BadState`, `PackMismatch` and their class), `crates/sim/src/
lib.rs` (`default_command_apply`, the skip attributes), `crates/harness/src/bin/ruage-headless.rs` (`--state-out`),
`crates/sim/tests/state.rs` (three fixtures).

## Performance

**Measured on the acceptance match, release build, 48,000 ticks, 149 entities:**

| quantity | value |
|---|---|
| state size | **59,108 bytes** (51,342 bytes at 200 ticks / 131 entities) |
| write (`World::state`) | **180 µs** |
| read (`World::from_state`, including the pack's tables and all nine players' cache rebuilds) | **2,882 µs** |

**Nothing on the tick.** No line of the tick's code changed; the write and the read happen when something asks for them, off the
tick path, and nothing in a running match calls either. The cost that matters is therefore zero per tick, and the two numbers
above are the whole price of a snapshot (0.18 ms to write, 2.9 ms to read, 59 KB for a 149-entity match - a save-tick
snapshot every 20 s would cost 0.001 % of a match's CPU).

**Why 59 KB for 149 entities**: the state is named fields, and the per-entity row is the whole entity (task, path, timers,
carried amount, construction, researching/training job), which is the point - a state that dropped any of those would tick
differently, and the round-trip fixture would say so.

## Stability

**Attack 1 - the load silently drops a field.** This is the failure mode a mirror struct invites, and it is why `serde` is
derived on `World` itself: a field added to the world appears in the document the next time the crate compiles, and the
round-trip fixture (hash equal immediately **and after 100 ticks**) fails if the load does not restore it. Three real
omissions were found this way while building it:

- **`units` and `economy` are pack data and were skipped** on the way out; not putting them back left the loaded world with no
  unit table, so every stat read as absent. The two worlds parted company on the **first step** after the round trip.
- **The obvious way to restore the pack - call `load_civs` - re-assigns each player's civ** from `economy.start.civs`. The
  start state is the match's, not the pack's, so a loaded world was given a *different civ* from the one its own state named,
  and the immediate hash stopped matching (which is how it was caught: the civ is hashed). The load installs the civ **table**
  and rebuilds the two caches instead.
- **`serde(skip)` needs a `Default`**, and `command_apply` has no sensible one (the pack's answer is not available while
  parsing). It has a documented placeholder that `from_state` overwrites before returning.

**Attack 2 - a corrupt file becomes a match.** A state cut in half is refused (`a_cut_state_is_refused`). No field is
defaulted: serde reports the missing one by name.

**Attack 3 - a state from another pack.** The tables are the pack's, not the match's, so the state carries the **identity** and
`from_state` refuses a mismatch by name, quoting both identities (`a_state_from_another_pack_is_refused_by_name`).

**Attack 4 - a derived cache that load forgot.** `bonus_tables` and `sight_modifiers` are `#[serde(skip)]`, so they cannot be
restored from the file: they are rebuilt. Forgetting one is a *test* failure, not a file that looks complete - which is the
whole reason they are not written.

**Attack 5 - the tick changes.** It does not: the acceptance hash is `2f1ab0ae663e2506` on **both** sides at 48,000 ticks
(149 entities, `repaths=432`, 90 body / 342 ground), built from `HEAD` and from the change.

**Hazard named, not fixed: forward compatibility.** A state written by a **newer** build - with fields this build does not know -
will load and silently drop them, because serde ignores unknown fields by default and `deny_unknown_fields` cannot be
combined with `flatten`. Nothing is affected today (one writer, one reader, same commit), but P1b must stamp a **version**
in the document and refuse one it does not know, before a converter starts producing states that outlive a build.

**Not attacked, and why.** The state is not compressed or checksummed: MessagePack plus the engine's own pack identity is the
integrity that matters here, and a byte that flips inside a valid stream is caught by the round-trip fixture in development
rather than by the reader at runtime. A save-tick snapshot ring (`every 20 s`, for the oracle's resumption) is a later slice
and nothing here forecloses it.

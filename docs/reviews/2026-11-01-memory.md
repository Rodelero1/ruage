# The memory: what it costs, and what it cannot see (2026-11-01)

Scope: `crates/sim/src/lib.rs` (`Sighting`, `World::memory`, `World::observe`, `World::sighting`, `observe_for`/
`observes`, the hash block, one call in `step`) and `crates/sim/tests/memory.rs` (6 tests, new). This is **D92**: a
player knows only what it has watched.

## Performance

Measured on this container (2 CPUs, 4 GiB), release, `cargo test --release -p ruage-sim --test perf -- --include-ignored
--nocapture`, idle worlds (units at rest) so what shows up is bookkeeping:

| entities | memory **off** (default) | memory **on**, all 8 seats | delta |
|---|---|---|---|
| 126 | 28.8 ns/entity/tick | 30.9 ns/entity/tick | +2.1 (+7%) |
| 376 | 26.8 | 41.1 | +14.3 |
| 626 | 28.2 | 43.9 | +15.7 |
| 1,126 | 25.3 | 44.4 | +19.1 |
| 2,126 | 25.1 | 45.1 | **+20.0 (+80%)** |

Baseline before this change was 25.3 / 23.7 / 24.0 / 23.3 / 23.8 ns per entity per tick, so **off is where it was**
(the 28.8 at 126 entities is noise on this box, and the only per-tick cost when off is one `any()` over eight bools).
Memory on costs about **+20 ns per entity per tick** at scale - 42 µs a tick on a 2,126-entity map, or 0.8 ms of CPU a
second at 20 Hz.

**The first version was 16x worse and it was measured, not guessed.** Built every tick for every player, the mask work
cost **380 ns/entity/tick** (824 µs a tick at 2,126 entities) - because `visible_mask` stamps a sight disc per entity,
so the price is `entities x sight area` per player. Two changes brought it down, in this order:

1. **Once a game second** (`tick % tick_rate_hz == 0`). No rule needs a fresher answer than its own cooldown, and a
   sighting stamped a second ago answers "seen within 30 s" identically.
2. **Off unless the match installs it** (`observe_for`). A bare world stays bare - the same shape as
   `apply_content_policy` (D75) - so the acceptance match, every scenario test and the probe pay one `any()` per tick.

A third change was an early return when fewer than two players hold anything; it is kept because it is free, but on the
eight-player probe it changed nothing, which is why it is not what fixed the number.

**The state hash does not move for a world without a memory.** Both blocks are written only when there is something to
write - an observing player, a sighting - so the acceptance match hashes exactly as it did (`91e869fcc92d606c`), and no
test needed re-baselining. That is deliberate: a rule that has never fired should not change a hash.

## Stability

Attacked, and what each attack showed:

- **An army nobody watched is unknown** - the whole point. A knight at (200, 200) with the observer at (60, 60) leaves
  `sighting` at `None` (test `an_army_nobody_has_watched_is_unknown`). If this ever regresses, the AI has become
  omniscient and no other test would notice.
- **A sighting outlives the sight** - the knight is deleted, two seconds pass, and the count and stamp are exactly what
  they were (`a_sighting_outlives_the_sight`). This is the difference between a memory and a view, and it is what makes
  "how stale is this belief" answerable.
- **One player's sighting is not another's** (`one_players_sighting_is_not_anothers`).
- **The stamp is the tick that has become current**, so `at == tick()` means "watched right now" and the age of a belief
  is `tick() - at`. My first version stamped before the tick advanced, which made every fresh sighting read as one tick
  old; the test caught it (`left: 1, right: 2`).
- **Determinism** - two worlds fed the same commands hold the same `BTreeMap` and hash alike
  (`a_run_of_the_same_world_produces_the_same_memory`). `BTreeMap` rather than `HashMap` for the hash-order reason that
  D89 made a lint.
- **A second enemy of the same type raises the count** (`a_second_enemy_of_the_same_unit_raises_the_count`) - the
  census is per pass, so it cannot drift upward across ticks.

### What is not attacked, and why it matters

- **The mask is built from unit and building sight discs; a garrisoned unit is not excluded.** A unit inside a
  building still contributes sight from its stale position, which the vision code has always done for the renderer too.
  If that is wrong it is wrong in one place, and the memory inherits it rather than adding a second opinion.
- **No test drives a sighting through the scenario runner.** `observe_for` is public and the tests call it directly;
  nothing wires it to `[[rule]]` yet, because no condition reads the memory until the next slice. When
  `enemy_at_least` lands, it must call `observe_for` for the players it serves - and the scenario test that follows is
  where the anti-cheat gate belongs.
- **A sighting is never removed.** The map grows with the number of distinct unit types ever seen - bounded by the
  pack's 1,389 units, so the ceiling is small, but it is a ceiling rather than nothing.

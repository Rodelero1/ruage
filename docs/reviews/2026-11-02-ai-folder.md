
## Addendum: the window was not playing the same game (2026-11-02)

Reported from `make run`: three villagers foraging berries, 290 food gathered, no villager trained, no building built -
while `make headless` reported gold mining and houses going up.

**Cause, found by reading the two entry points side by side.** `crates/view/src/bin/window.rs` seeded the world, loaded
combat and called `apply_content_policy()`, and stopped there. It never loaded research, never loaded the civ table, and
**never loaded a scenario** - so no rules were ever installed. The content policy only *reallocates* villagers among
resources; without rules nothing trains, nothing builds, and the economy is three villagers on a bush forever. The
headless runner loads research, civs and the scenario, which is why it and the window disagreed.

**Fix:** the window now loads `gamedata/techs.toml`, `gamedata/effects.toml`, `gamedata/civs.toml` and
`acceptance.toml`, installs a `Runner`, and applies `runner.due(&mut world)` before each tick - the same order the
headless runner uses. Compile-verified only: this container has no display, so the window path is not exercised by the
suite, and the honest statement is that the *loading* is now identical, not that the picture has been seen working.

**Why the suite did not catch it:** the view crate's tests drive `render` over a `Snapshot`, and the binary's seeding is
untested. A GUI entry point is not covered by a headless suite unless the wiring is extracted into a function both
entry points call - which is the durable fix, and is the next thing this file owes.


### Performance

The window now parses what the headless runner always parsed, at startup and once: **techs.toml 93,165 B + effects.toml
346,739 B + civs.toml 37,812 B + acceptance.toml 1,107 B = 478,823 B****, against a seeding step that already parses
`units.toml` at 521 KB. Per tick the added work is `runner.due()`, which is what the headless runner has always paid:
the acceptance suite that exercises it runs a simulated minute in **61.5 s** of wall clock for 22 tests, unchanged by
this edit because the sim path did not change.

Nothing was added to `render`, to `Snapshot`, or to the tick.

### Stability

- **A missing table is now a refusal at startup**, with the file named (`techs.toml: ...`), instead of a window that
  opens and shows an idle economy - the failure mode the owner actually saw.
- **Order matches the headless runner**: research, civs, policy, then `Runner::due` before `step`. Divergence between the
  two entry points was the bug; the fix is that they now do the same sequence in the same order.
- **Unverified by the suite**: the binary's wiring has no test because it needs a display. The review says this plainly
  rather than implying coverage, and names the durable fix - one `seed(config) -> (World, Runner)` function called by
  both binaries.

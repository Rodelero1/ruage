Final task of the Full New Way plan. Tasks 1–5 landed the geometric solver
end-to-end, routed every mover through it, deleted the tile system and rebased
conformance. This task owns the close-out: the deck edge cases as committed
witnesses, the debug scaffolding removal, the two ADR rewrites, and the
measured before/after. Task 3's two deferred minors (turn-count accumulates
across shapes; doubly-inside start can answer a single inside point) and the
unit-target gating narrowing are untouched — final-review pointers, not this
task.

## Performance

Measured, same box, debug profile unless marked release. Before = `ae3b0de`
(pre-deletion tree, tile system) in a throwaway worktree with the same
generated gamedata copied in; after = HEAD. The harness file is identical on
both sides.

- Acceptance scene (`the_acceptance_match_banks_food`, 8000 ticks at 20 Hz,
  debug): before 16.54 s → after 71.94 s (4.3x; ~2.1 ms/tick → ~9.0 ms/tick).
- Hundred units planning in one tick (debug): before 167.8 ms
  (1677.6 us/unit) → after 2813.9 ms (28138.9 us/unit), 16.8x on the burst
  tick; the next nine walking ticks before 519.8 ms (57.8 ms/tick) → after
  678.1 ms (75.3 ms/tick).
- Hundred units planning in one tick (release): before 13.7 ms
  (136.5 us/unit) → after 161.2 ms (1612.5 us/unit), 11.8x on the burst
  tick. Walking ticks (release): before 57.1 ms over nine (6.3 ms/tick) →
  after 79.0 ms over nine (8.8 ms/tick), 1.4x.
- Solver micro-probes from Tasks 2–3 (release, still true — solver untouched):
  `ray_hit` 62 ns/op, `walk_shape` 348 ns/op, `solve` 2069 ns/op over a 3-box
  scene. The unit-level solver is cheap; the world-level cost is per-mover
  replans and forays, not the geometry core.
- Full `ruage-sim` suite: green except the two pre-existing `modifiers`
  failures (Town Watch LoS numbers, reproduce without this slice — see
  Stability); the twelve geometry-solve witnesses run in under 1 ms.

The burst-tick regression is real and is reported as measured, not explained
away: one tick planning a hundred cross-map routes costs more under geometry
than under budgeted tile A*. The spec's gates are functional
(never-stuck/never-through-blocked) and hold — every number below certifies
the answers, not the stopwatch — but anyone signing this should know the
planning burst got slower before they do. Mitigating context, not an excuse:
a hundred simultaneous cross-map plans in one tick is a pathological burst,
real games spread plans across ticks, and the steady-state walking tick moved
far less (debug 57.8 → 75.3 ms/tick; release steady-state pending). Debug
profile inflates everything ~12x (before-tree 167.8 ms debug vs 13.7 ms
release on the same harness).

## Stability

- Attacked with a scratch fuzz harness (deleted before commit, 2000 random
  scenes, 0–4 boxes, seeded xorshift so the run repeats): 0 empty answers
  (stuck-probe — the solver never refuses), 0 `verify_path`-unclean answers
  (through-wall probe — no leg ever passes inside a grown box), 0
  run-to-run differences (determinism hash `30b5ebfdf409396d`, identical on
  re-run). Fixed-point only; no float enters the walk.
- Bounds terminate by construction (Task 3, unchanged): every accepted step
  strictly decreases the exact integer squared distance, and the fuel cap, the
  expand-once flag and the hole turn-count each force `Closest` when no step
  qualifies. The long-wall witness pins the guard under pressure: no way round
  inside the bounds answers Closest beside the wall, never a wander and never
  a crossing.
- The full suite is the standing stuck-probe: `stuck`, `stall`,
  `crowd_piles_up`, `no_room`, `gather_room` and the acceptance match all
  pass — no mover wedges, no refusal where a route exists, food banks by
  400 s and the crew grows by 800 s.
- Pre-existing, untouched: 2 `modifiers` failures (Town Watch LoS numbers) and
  the `world/step.rs:29` clippy error both reproduce on clean HEAD without
  this slice; neither file references geometry. New/changed files are
  clippy-clean under `-D warnings` and `cargo fmt --check` clean.
- Own errors this slice: one bad edit while removing `SCRATCH_P` left a bogus
  assertion in `passage.rs` (repaired immediately — deletion only, no
  replacement); one fuzz-harness borrow error (closure over `rng`, fixed with
  a `mut` binding). Both fixed, final diff re-tested.
- Known limitations (not attacked further): Task 3's two deferred minors
  still stand (turn-count accumulates across shapes, delaying the hole stop by
  one circuit; a doubly-inside start can answer a single inside point);
  `Closest` is the walk's nearest certified point, not a globally nearest
  reachable point.

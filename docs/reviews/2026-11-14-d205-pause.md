# D205's rule, built and measured: the pause is right and it is not enough

**Branch `d205-pause`, from `bb467dd` (`main`). No production change is proposed for `main`.** This branch builds D205 as
the decision states it - the lower entity id has right of way, the higher id is paused for a uniform 0.25-1.50 s and keeps
its path, and the give-way mutex, the axis/perpendicular slide and the nudge are gone - and then measures it. **The rule is
faithful to the binary and the engine cannot move under it**: with the three improvisations removed, the winner of a
collision has no way past the man it just paused, the economy of the acceptance match freezes at 10 food and 13 units for
the whole forty minutes, and **33 tests in 21 binaries go red**.

This note is the record of that, not a request to land it.

## What changed

| file | change |
|---|---|
| `crates/sim/src/world/movement.rs` | rules 4, 5, 6, 9 of `collide` replaced by one tie-break (rule 4): `other.0 > id.0` -> the other man is told to pause and this body proceeds, otherwise this body is the one paused and returns `StepDecision::Paused` before the repath, so its route is untouched. `wait_or_give_way` deleted. `bound_to_reach` kept, for the one case D205 does not withdraw (rule 6, a body at rest). |
| `crates/sim/src/world/step.rs` | `push_the_standing` (D200's displacement) deleted with its call; the make-room loop and `Route::gave_way` deleted; `move_bodies` skips a paused body before `collide`, spends no waypoint for it, and draws the duration for every body a collision paused, from `sim_rng`. |
| `crates/sim/src/lib.rs` | `Entity::pause_remaining: u16` (ticks); `PAUSE_MIN_MS = 250`, `PAUSE_SPREAD_MS = 1251`; `StepDecision::{MakeRoom, GiveWay, GiveWayOwnTile, WaitOwnTile}` removed, `Paused` added; `Passing::{made_room, refused}` -> `pauses`; `World::route_points` added so a test can read a body's waypoint list. |
| `crates/sim/src/world/state.rs` | `pause_remaining` hashed when non-zero. |
| `crates/sim/tests/right_of_way.rs` | the three fixtures D205 was accepted on, written before the change (D7). |

The draw is `250 + roll % 1251` milliseconds (the original's `rand()*1.25/32767+0.25`, 0.25 to 1.50 s inclusive) converted
once with the tick rate; the tick the collision was found on is already stood still, so the timer keeps what is left of the
duration (`ticks - 1`). No float enters state and `no_float` is green. A paused body is not re-paused while its timer runs:
`collide` is never reached for it.

## The green run, on this branch: the pause works, the pair does not move

The pause itself is right, and the test measures it exactly: **the higher id stood still for a run of 5-30 ticks whose
length equals the drawn duration, its waypoint list was the same list before and after, and the lower id moved during it** -
all three assertions pass on the branch. What fails is everything after the pause:

```
MEASURED the higher id stood still for 2431 ticks (121.550 s): a pause is bounded at 1.50 s by the original's own draw,
and a longer stand is a freeze by another name

MEASURED a unit jammed on one tile stood still for 2500 ticks (125.000 s) at the longest: a pause is bounded at 1.50 s,
so a longer stand is the freeze by another name
```

### Why, measured

A probe over the same fixture, printing both men's decision and route every tick:

```
t 50 lower ( 230800, 170000) Take      path 1 | higher ( 249200, 170000) Take   path 1 pause 0
t100 lower ( 236400, 170000) WaitBlocked path 2 | higher ( 244400, 170000) Paused path 1 pause 17
t150 lower ( 236400, 170000) WaitBlocked path 2 | higher ( 244400, 170000) Paused path 1 pause 18
...
repaths 1 body 1 ground 0 failures 0 made_room 0
route [(264000, 156000), (290000, 170000)]        <- the winner's re-plan, first waypoint on the FAR side
```

1. The pair stops at **8000 raw units = exactly the two 0.2 radii** - `blocker_at` calls that distance clear, and
   `bound_to_reach` allows no step that would end inside it, so **the winner's bounded step is exactly zero** there. The
   winner is `WaitBlocked` from tick 70 to the end of the run.
2. The winner's escape is supposed to be the **repath**, and the repath is tile-based: `avoiding` is a set of *tiles*, and
   `short_range` drops the mover's own start tile from the obstacle set ("an avoid set that holds it makes the search leave
   the tile it starts in"). When the two men are in one tile - which is the 2026-11-13 geometry - **the repath cannot
   express the blocker at all** and returns the straight line it already had.
3. When they are in adjacent tiles the re-plan does produce a detour, and the detour does not help either: the mover's disc
   already overlaps the avoided tile's expansion by 400 raw units, so the graph's first waypoint is the **far** corner
   (`(264000,156000)` above), and the step toward it is still blocked by the paused man.

So the pause bounds the *loser* and the winner has nothing to proceed with. D205's own claim - *"a pause is bounded by a
countdown, so the pair can never stand for ever"* - **does not hold on this engine**, because it assumes the winner's
repath can route round a body, and ours routes round tiles.

## Performance

- **Like for like, `perf::a_ten_minute_match_in_release`** (same map, 128 entities, 12,000 ticks, `--release`), three runs
  on this branch: **6.91 / 7.02 / 7.33 us per tick**, against the **6.5-6.8 us** recorded for `main` after D204. About
  **+2% to +8%**, which is what one field read and one saturating decrement per body per tick cost; the pause check is a
  load and a compare on a field that was already in the same cache line as the entity.
- **The acceptance wall time reads 4.8 s against `main`'s 30.3 s**, and that number is **not** an improvement: the match
  has almost nothing left to do. Quoted here only so nobody misreads the table.
- No allocation was added to the pass: `Passing::pauses` is the same `Vec` the withdrawn `made_room` held, and `BTreeSet`
  dedup is a handful of ids a tick at most.

## Stability

- **33 tests in 21 binaries are red** (813 passed, 22 ignored, 187 binaries): the crowd and gather families
  (`a_gatherer_walks_round_a_friend_standing_in_his_path`, `the_villager_walks_to_the_node_and_then_takes_from_it`,
  `a_full_villager_carries_the_wood_home`, `a_crowd_ordered_to_one_tile_all_arrive_and_spread`,
  `a_man_who_cannot_get_his_square_takes_the_next_tree`), the economy-driven age/train tests, and the two new fixtures.
  Every one of them is the same shape: a body that has to get past another body and cannot.
- **The failure is geometric, not universal, which is why the count is 33 and not all of them.**
  `evasion.rs::two_villagers_crossing_pass_through_and_both_arrive` and all four tests in `collision.rs` are **green**: a
  crossing resolves when the pair meets where the winner's re-plan can find a tile to go round. It deadlocks when the two
  bodies come to rest at **exactly** the reach - `bound_to_reach` then has no step that fits, and the pair is at a knife
  edge the tick arithmetic lands on more often than not (1600 raw closed per tick against a 8000 raw standoff is a whole
  number of steps). That is why the acceptance match, with men packed round the town centre and at every node, stops dead
  while a lone pair on an open row gets through.
- **`a_blocked_unit_goes_round_a_standing_body_and_arrives` (evasion.rs) is red**, and it is the most telling: the
  walker is the *lower* id there, so it has right of way, the sitter is told to pause, and the walker still cannot step -
  `WaitBlocked`, the assertion "it arrives" fails. On `main` the slide and the give-way are what carried it past.
- **No new panic, no overflow, no unbounded loop**: the draws are `u32` remainders and the timer is saturated; a paused
  body is skipped before `collide`, so no route, task or counter runs twice for it. `pause_remaining` is state and is
  hashed, so a replay of a fixture with a collision still reproduces to the tick - the old hashes are simply not the same
  ones, which D205 accepted.
- **The freeze is a standstill, not a hang**: the acceptance run completes 48,000 ticks in 4.8 s. It is worse than a hang
  in one way - the world looks alive (ticks advance, the script keeps trying) while nothing is produced.

### The three ways out, and why none is taken here

1. **Make the repath body-aware** - avoid an *entity's disc*, not a tile (0 A.D. inflates the moving body and tests
   circles). This is the faithful fix and it is a pathfinder change, not a collision one: `short_range`'s graph and
   `find_path_avoiding` both take a tile set. It would also fix the adjacent-tile case in the probe above.
2. **Keep one lateral step for the winner** - re-introduce the slide (rule 5) for the body that has right of way. It would
   work and it is a reintroduction of what D205 removes, so it needs the owner's word.
3. **Let the winner step through a paused body** - `Rule 3`'s "already inside" lease, extended to the man it just paused.
   It works, and it walks two bodies through each other for a step, which is D189's pass-through that D200 withdrew and
   `collision.rs::a_walker_never_ends_a_tick_inside_a_friend` and `evasion.rs::a_body_on_the_goal_is_never_entered...`
   forbid.

Option 1 is the only one that leaves both D205 and D200 standing, and it is a separate slice with its own tests.

## Where the branch stands

- The rule is built to the binary's own reading, tested for the pause length, the kept waypoint list and the lower id moving.
- The replacement is **not sufficient**: the winner's repath cannot route round a body, so the pair stands while the loser
  is paused, and the acceptance match freezes at 400 s.
- **Not mergeable, and not merged.** `main` is untouched at `bb467dd`. The next step is `docs/next-step.md` step 1: a
  body-aware re-plan, test-first, with `crates/sim/tests/right_of_way.rs` as its acceptance.

## Second pass: the winner's tangent, and where it stops

The pause measured correctly on this branch and the match still would not move, so the geometry was chased one layer further.

**What was added.** Rule 6 (blocker at rest) and rule 7 (blocker moving) both tried a **tangential** step when the straight one
bounded to zero: a step *along* the circle the reach protects rather than across it, so it costs no overlap. Measured on the
acceptance run (`--seed 7 --ticks 48000 --report 400`):

```
before the tangent   flat: wood 20 food 44 units 28 buildings 8 from 400 s to 2,400 s
after  the tangent   wood 100/67/96/112/112/112  food 20/28/314/338/697/797  units 18/26/36/51/51/51  buildings 8/25/33/26/24/24
```

Eight loaded carriers had been queued at one drop site, each holding ten, none banking: the man in front was **moving**, so
rule 7 stood the man behind still, and the tile-based re-plan cannot see a body. The tangent is what emptied that queue.

**Where it stops - the whole workspace gate, 187 binaries, 828 passed, 18 failed.** The tangent is a *path* change, not a
collision fix, and it collides with rules the project wrote for stances and gathering:

```
stances     no_attack_walks_past_an_enemy, a_plain_move_walks_past_the_same_enemy,
            a_stand_ground_unit_keeps_walking_past_an_enemy   (a unit now slides round a moving enemy)
gather      a_full_villager_carries_the_wood_home, the_rate_is_the_variants_work_rate_per_tick,
            a_depleted_worker_takes_the_next_tree_it_can_see, a_gatherer_stands_beside_the_node_and_not_on_it,
            a_content_pack_with_our_own_resources_loads_and_spends, a_gathering_minute_reports_delivered_resources_and_nothing_else,
            a_man_who_cannot_get_his_square_takes_the_next_tree, a_closer_lumber_camp_wins_over_the_town_center
rally/train a_unit_rallied_to_its_own_building_stays_inside, a_villager_rallied_onto_stone_gathers_stone_not_the_wood_around_it,
            a_barracks_trains_a_spearman_once_the_feudal_age_is_reached, a_barracks_cannot_train_a_spearman_in_the_dark_age,
            a_trebuchet_cannot_be_trained_before_the_imperial_age
vision      an_enemy_is_only_visible_while_somebody_watches
```

**The reading.** D205's own rule is right and is measured: the pause is the drawn 0.25-1.50 s, the loser keeps its waypoint
list, and the man with the lower id gets through. What is missing is underneath it: the original's re-plan avoids **bodies**,
ours avoids **tiles**, so every crowd answer has to be a step rule - and every step rule we add is another way for a unit to
leave the line a test wrote down. That is why the three previous attempts (give-way, slide, nudge) all ended as exemptions.

**Conclusion: parked, not landed.** The two cheap options both change gameplay the owner has already ruled on (a lateral step
for the winner, or letting the winner overlap a body it just paused), and the right one - a search that plans round bodies -
is a slice of its own. `main` stays as it was: D204's rule with the slide and the nudge that keep 843 tests green.

## Third pass: the re-plan was never re-planning (and the impasse this proves)

The owner chose "a search that routes round a body". Three faults were found and fixed on this branch:

1. **`short_range` answered "walk straight through him".** Its fast path returned the straight line when no *tile* was
   blocked (`blocked.is_empty()`), so a re-plan asked to avoid a body in open ground was never a re-plan. Measured: the
   winner `WaitBlocked` at `+8000 raw` for 2,500 ticks with the body in its own avoid list.
2. **A body was treated as ground.** Each avoided unit's tile was expanded by the *mover's* radius, so a waypoint could sit
   0.2 of a tile from a 0.2 body - inside the reach the step bound refuses. `short_range_around` expands each body by the
   **pair's** reach and lets a start already inside that zone leave it (a man who has met someone is inside it by
   definition).
3. **The exemption never expired.** A route kept a permanent pass for a man it had planned round once, where the original
   treats a body as "past" only while it has not moved since the path was created. The avoid set is now a map
   `EntityId -> position-at-plan-time`, and the exemption lapses when the body leaves that ground.

Result: `right_of_way` 3/3 green, and with the tangent disabled `gather` green - the rules work in isolation.

**The whole-workspace gate, 187 binaries: 815 passed, 31 failed.** And the counterfactual that closes the question:

| step rules | `right_of_way` | gather / felling / evasion |
|---|---|---|
| re-plan only (no lateral step) | 2 red - the pair still jams at the exact reach | `gather` green, `evasion` 2 red (a blocked unit cannot get past a standing body) |
| re-plan + own-tile tangent | 3 green | 31 red across gather, felling, shepherd, lumber camp, rally, vision |

So the two halves of the requirement are in direct conflict *at tile resolution*: a lateral step is what gets a man past a
body, and a lateral step is what takes a gatherer off his square. No arrangement of step rules satisfies both, because the
search itself cannot express "pass beside this body" - it is a visibility graph over **tiles**, seeded from the mover's own
position, and a man who has met someone is standing inside the body's reach already.

**Conclusion: the missing half is the search, as a slice of its own.** D205's rule (the pause, the waypoint list, the id
tie-break) is right and measured; what it needs underneath is a pather that plans in **free space** - nodes offset from the
body's disc rather than tile corners - which is what the original's obstacle set gives it. That is a change to
`short.rs`'s graph construction, not to `collide`.
